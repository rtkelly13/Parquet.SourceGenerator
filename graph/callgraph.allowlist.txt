# Call-graph allowlist (#252) — every cycle the gates would otherwise reject, with
# the reason it is legitimate. Same philosophy as CodeMetricsConfig.txt and
# src/api/seams.txt: exceptions are counted, named, and meant to come off.
#
# Formats:
#   SELF	<exact	method id> <reason>       direct self-recursion
#   SCC	 <id | id	| ...> <reason>         a multi-node strongly-connected component
#
# The TargetParser compound-model cycle is the parser walking a nested [ParquetSerializable]
# tree: CollectMembers -> CollectMember -> TryCollectCompoundMember -> BuildCompoundModel ->
# CollectMembers (one level down), with BuildNestedElementModel handling list elements and
# map values on the same descent. Parquet schemas are trees; recursion is the correct shape
# (#176/#182's design), and the containment path + MaxCompoundDepth bound it. This is the
# issue's explicitly blessed case ("the compound model parser is genuinely recursive over a
# tree") — not mutual recursion across components. A type adapter's structural surrogate
# (docs/44-TYPE-ADAPTERS.md) is planned by the same descent: PlanSurrogate -> BuildCompoundModel.

SELF	Parquet.SourceGenerator.Emitter.Compound.CompoundMapping.EmitLadder/(StringBuilder,LeafColumn,string,int,string,string)	Definition-ladder shredding walks one level of the Parquet definition tree per call (#185); depth is bounded by the schema the parser already capped.
SELF	Parquet.SourceGenerator.Emitter.Compound.CompoundSchema.GetFieldCreationExpression/(PropertyModel,string)	Struct fields contain structs; the field creation recurses to emit the nested DataField tree.
SELF	Parquet.SourceGenerator.Emitter.Compound.EmissionPlan.WalkStruct/(PropertyModel,StructNode,int,int[],int,bool[],bool[],InlineAdapterModel?[],bool[],string[],List<LeafColumn>,List<StructNode>)	The compound plan walk follows the child tree of a struct member; the recursion IS the traversal.
SCC	Parquet.SourceGenerator.Parser.TargetParser.BuildCompoundModel/(PropertyKind,ITypeSymbol,string,ITypeSymbol,string,int,bool,ParquetApiLevel,string,Location,List<DiagnosticInfo>,HashSet<INamedTypeSymbol>,int,CompoundKinds,bool,string?,bool) | Parquet.SourceGenerator.Parser.TargetParser.BuildNestedElementModel/(ITypeSymbol,string,ParquetApiLevel,string,string,Location,List<DiagnosticInfo>,HashSet<INamedTypeSymbol>,int,CompoundKinds,bool) | Parquet.SourceGenerator.Parser.TargetParser.CollectMember/(ISymbol,MemberScope,MemberSink) | Parquet.SourceGenerator.Parser.TargetParser.CollectMembers/(INamedTypeSymbol,MemberScope,MemberSink) | Parquet.SourceGenerator.Parser.TargetParser.CollectThroughAdapter/(AdaptedMember,AdapterDescriptor,ColumnOptions,LeafOptions,MemberScope,MemberSink) | Parquet.SourceGenerator.Parser.TargetParser.PlanElementSurrogate/(AdaptedMember,AdapterDescriptor,ITypeSymbol,bool,MemberScope,bool) | Parquet.SourceGenerator.Parser.TargetParser.PlanSurrogate/(AdaptedMember,AdapterDescriptor,string,string,ColumnOptions,LeafOptions,MemberScope,bool) | Parquet.SourceGenerator.Parser.TargetParser.TryCollectAdaptedList/(AdaptedMember,ColumnOptions,MemberScope,MemberSink) | Parquet.SourceGenerator.Parser.TargetParser.TryCollectAdaptedMember/(AdaptedMember,ColumnOptions,LeafOptions,MemberScope,MemberSink) | Parquet.SourceGenerator.Parser.TargetParser.TryCollectCompoundMember/(ISymbol,ITypeSymbol,ITypeSymbol,ColumnOptions,bool,Location,MemberScope,MemberSink)	The #176 compound parser descending a nested-model tree; bounded by MaxCompoundDepth and the containment path (PARQ012/PARQ013). One module, tree recursion — the issue's blessed case. The adapter path (TryCollectAdaptedMember -> CollectThroughAdapter -> PlanSurrogate -> BuildCompoundModel) joins the same descent for a structural surrogate, one level down; members inside a surrogate may be adapted in turn (docs/44 §A.4c), and every such level passes through BuildCompoundModel, so the containment path (PARQ012) and MaxCompoundDepth (PARQ013) bound it exactly as they bound nested models. An adapted collection element's group surrogate (TryCollectAdaptedList -> PlanElementSurrogate -> BuildCompoundModel) is the same one-level descent (docs/44 §A.4b).
